| แจกแชตตามสถานะ `F11` | A1 | พนักงานตั้ง **ว่าง / พัก / นอกเวลา** เมื่อร้านเปิด auto-assign ให้เลือกเฉพาะพนักงานที่ว่างและมีสิทธิ์ ถ้าไม่มีให้แชตอยู่ในคิว `รอพนักงานรับ` |
| กระดิ่งข้อผิดพลาด `F31` | C3 | ทำ S1 สำหรับรายการในแอปและสถานะอ่าน/ยังไม่อ่าน ใช้ event จาก F10/F35 ที่มีข้อมูลร้านและเกิดหลังลองใหม่จนครบ ให้ C3 ทำหลังงานตั้งค่าร้าน/สิทธิ์ของ P0 และให้ Lead จัดลำดับกับ `F02` |

## ส่งต่อโดยไม่ใช้โทเคนเกินจำเป็น

1. **ลด scope B1 ก่อน Gate** งานคลังความรู้ ค้นหา และสินค้าใช้ขั้นต่ำรวม 135 นาที เทียบกับเวลา 130 นาทีจาก `SETUP READY` ประมาณ 10:50 ถึง Gate ให้ส่งส่วนที่เพิ่มข้อมูล แก้ราคา และค้นคืนราคาได้จริงก่อน เก็บหน้าจัดการเต็มไว้หลัง Gate หาก Lead แบ่งงานให้เปลี่ยนเจ้าของและ path ให้ชัดก่อนเปิด PR · **ทำแล้ว (21 พ.ย.):** ลำดับเริ่มต้นของ B1 คือ F05 S1 → F08 S1 → F07 S1 → F08 S2a (เพิ่ม/แก้สินค้าหนึ่งรายการพร้อมราคา) รวม 130 นาที ส่วนที่เหลือของหน้าสินค้าเป็น S2b หลัง Gate ([F08 §14](../specs/F08-catalog.md))
2. **ส่งหลักฐานจากเจ้าของ dependency ก่อน** B1 ส่ง lookup/ราคาให้ B2 และ A1 ส่ง Inbox/รับช่วงให้ B2 กับ C2 ส่วน C1/B2 ส่งผลล้มเหลวที่ต้องแจ้งให้ C3 ทำกระดิ่งได้ ข้อความเดียวระบุ `ref`, `TO:<lane>`, PR/SHA และผลทดสอบหนึ่งบรรทัด
3. **ใช้ trace เดิมทำฟีดแบ็กร้าน** เช่น คำถามค่าส่งที่เจอบ่อยและค้นไม่เจอ หรือค่าร้านตั้งให้ไม่เปิดเผยราคา เก็บเคสมีข้อมูล เคสข้อมูลขาด และเคสคนรับช่วงสำหรับทดสอบซ้ำ แล้วใช้ผลที่วัดได้ใน `F37/F27` ตามเวลาที่เหลือ
4. **คุมงบตาม checkpoint** ใช้ Standard เป็นหลัก Fast ของ GPT-6.2 Sol ใช้โควตาหรือเครดิต 2 เท่า เลือกใช้กับงานที่ขวางเดโม ตรวจ usage เวลา 11:30, 13:00 และ 14:30 ถ้า Gate ช้าให้พัก P3 และ P2 ก่อน เก็บเวลาทดสอบและหลักฐานหลังหยุดเพิ่มฟีเจอร์ **15:30** ล็อก deploy **16:45** และส่ง **17:00**
